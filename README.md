# TK Tracker - BF1 违规记录插件

TK Tracker 是一款轻量级 AstrBot BF1 群管辅助插件，用于自动记录管服机器人的踢人播报，让群管理员能够快速查询玩家历史、查看违规排行并分析阶段数据。

插件基于 Python 内置 SQLite 增量存储，无需额外运行依赖；数据库操作通过单线程后台队列串行执行，同时支持群聊数据隔离、服务器筛选、重复播报拦截、风险分析、操作审计和高风险清空二次确认，适合单群或多群、多服务器场景长期运行。

## 主要功能

- 按 AstrBot 会话隔离数据，不同群聊的记录和排行互不影响。
- 支持机器人与服务器名称映射，并可按服务器筛选。
- 使用消息 ID 和时间窗口拦截重复播报。
- 使用索引化摘要匹配重复播报，历史记录较多时仍保持轻量。
- 使用汇总表维护玩家累计次数，排行榜不扫描全部历史记录。
- 数据库读写进入单线程后台队列，减少阻塞机器人消息处理。
- 支持玩家风险概况和可选的自动风险提醒。
- 支持运行状态、管理员操作审计、数据库备份和 CSV 导出。
- 清空全部记录必须在 30 秒内二次确认，并默认先自动备份。
- 支持最近 1 至 365 天违规统计和常见原因排行。
- 支持静默模式、查询限流、数据保留期限和导出上限配置。
- 自动升级 1.1.0 SQLite 数据库，并兼容更早的 `records.json`。

SQLite 来自 Python 标准库，不需要安装额外依赖。

## 安装与升级

1. 将 `astrbot_plugin_tk_tracker` 文件夹放入 AstrBot 的 `data/plugins/` 目录。
2. 在 AstrBot 控制台重载插件。
3. 在插件配置中填写超级管理员和管服机器人账号。
4. 多个管服机器人对应不同服务器时，配置服务器名称映射。

从 1.1.0 或 1.2.0 升级时，数据库会原地增加字段和索引，不会删除记录。旧记录没有会话信息，因此会在升级后的首次群聊指令或群内播报发生时，自动绑定到该群聊；私聊不会触发绑定。

## 服务器名称配置

`bot_server_map` 每项使用以下格式：

```text
123456789=一服
987654321=二服
```

没有配置名称时，插件使用管服机器人账号作为服务器标识。

## 指令

| 指令 | 功能 | 权限 |
| --- | --- | --- |
| `/tk帮助` | 查看简明帮助 | 所有人 |
| `/tk查 <玩家ID> [服务器]` | 查看累计次数和最近记录 | 所有人 |
| `/tk排行 [服务器]` | 查看当前会话违规排行 | 所有人 |
| `/tk统计 [天数] [服务器]` | 查看阶段统计和常见原因 | 所有人 |
| `/tk风险 <玩家ID> [天数] [服务器]` | 查看近期风险概况 | 所有人 |
| `/tk删除 <记录编号>` | 删除当前会话中的单条记录 | 管理员 |
| `/tk清空 <玩家ID> [服务器]` | 删除玩家记录 | 管理员 |
| `/tk清空全部` | 申请清空当前会话全部记录 | 管理员 |
| `/tk确认清空` | 在 30 秒内确认清空操作 | 管理员 |
| `/tk审计 [条数]` | 查看最近的管理操作 | 管理员 |
| `/tk状态` | 查看数据库和后台任务状态 | 管理员 |
| `/tk备份` | 立即备份数据库 | 管理员 |
| `/tk导出 [天数] [服务器]` | 导出当前会话 CSV | 管理员 |

示例：

```text
/tk查 Alice
/tk查 Alice 一服
/tk排行 二服
/tk统计 30 一服
/tk风险 Alice 7 一服
/tk删除 105
/tk导出 30 一服
```

## 播报格式

发送者必须位于管服机器人白名单中，消息需匹配：

```text
踢出玩家 <玩家ID> 成功
原因：<违规原因>
```

关键词之间可以有换行或多个空格。

## 数据与资源占用

新版本优先使用 AstrBot 官方插件数据目录：

```text
data/plugin_data/astrbot_plugin_tk_tracker/records.db
```

旧版 AstrBot 不支持统一数据目录时，回退到插件内部：

```text
data/tk_tracker/records.db
```

插件不会把全部记录载入内存。数据库操作由单线程后台队列串行完成，每次播报只进行一次小型事务，排行榜直接查询汇总表。管理员操作审计保存在同一个 SQLite 数据库中。

备份和导出文件分别保存在插件数据目录的 `backups/` 和 `exports/` 中，默认仅保留最近 10 份备份和 20 份导出，避免文件长期累积。`retention_days` 默认为 `0`，即违规记录永久保留；只有管理员明确配置大于 `0` 的天数后，插件才会定期清理过期记录。自动风险提醒也默认关闭。
